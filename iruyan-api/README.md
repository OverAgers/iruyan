# 📁 プロジェクト ディレクトリ構成

| パス               | 内容                                                                                       |
| ------------------ | ------------------------------------------------------------------------------------------ |
| `Dockerfile`       | Go アプリケーションをビルドするための設定ファイル。依存パッケージやビルド方法を定義。      |
| `README.md`        | プロジェクト概要、導入方法、使用方法、開発者向けの情報を記載。                             |
| `docs/`            | Swagger で生成される API ドキュメント（`docs.go`, `swagger.json`, `swagger.yaml` など）。  |
| `go.mod`, `go.sum` | Go Modules による依存関係の管理ファイル。                                                  |
| `main.go`          | アプリケーションのエントリーポイント。Gin ルーターやミドルウェア、サーバー起動などを定義。 |

## 📦 ディレクトリ構造の詳細（MVC + Clean Architecture 寄り）

### handlers/ – コントローラ（Controller 層）

| パス     | 内容                                 |
| -------- | ------------------------------------ |
| `auth/`  | ログイン・ユーザー登録などの認証機能 |
| `error/` | 共通エラーレスポンスハンドラ         |
| `room/`  | ルーム作成、入退室のハンドラ         |
| `user/`  | ユーザー情報の取得・管理             |

### models/ – モデル（Model 層）

| ファイル名    | 内容                                                 |
| ------------- | ---------------------------------------------------- |
| `room.go`     | ルームモデル。名前や ID、バリデーションなどを定義    |
| `seat.go`     | シートモデル。座席番号やルームとのリレーションを管理 |
| `user.go`     | ユーザーモデル。パスワードのハッシュ化なども担当     |
| `worktime.go` | ユーザーの入退室記録や作業時間を管理するモデル       |

### responses/ – ビュー（View 層）

- 各エンドポイントの共通レスポンス形式（成功/失敗時）を定義。
- フロントエンドとの I/F を統一し、開発の可読性・保守性を向上。

### routes/ – API ルーティング

| ファイル名       | 内容                                   |
| ---------------- | -------------------------------------- |
| `auth_routes.go` | 認証系エンドポイント（ログイン、登録） |
| `room_routes.go` | ルーム関連（作成・入退室など）         |
| `user_routes.go` | ユーザー情報取得・更新など             |

### infrastructure/ – インフラ層

- DB 接続など、アプリ外部リソースとのやりとりを担当（例：`infra.DB`）。
- アプリケーション本体とは疎結合になるよう設計。

### middleware/ – 共通処理層

- CORS 設定、ログ出力、エラー処理などの共通処理を担う。

### tmp/ – 一時ファイル/ログ保存

| ファイル名         | 説明                              |
| ------------------ | --------------------------------- |
| `build-errors.log` | Docker ビルドやアプリ実行時のログ |
| `main`             | コンパイルされた実行ファイル      |

# 🧩 アーキテクチャのポイント

この構成は MVC（Model-View-Controller） および クリーンアーキテクチャ をベースにしています。

| 層             | フォルダ               | 役割                          |
| -------------- | ---------------------- | ----------------------------- |
| モデル層       | `models/`              | データ定義・バリデーション    |
| ビュー層       | `responses/`           | レスポンス構造の標準化        |
| コントローラ層 | `handlers/`, `routes/` | リクエスト処理・ルーティング  |
| インフラ層     | `infrastructure/`      | DB 接続や外部サービスとの連携 |
| ミドルウェア層 | `middleware/`          | CORS やロギング等の共通処理   |

# 📘 Swagger API ドキュメントの使い方

## Swagger UI の確認手順

1. サーバーを起動する：

```
docker-compose up --build -d
```

2. ブラウザで以下にアクセス：

```
http://localhost:8080/swagger/index.html
```

## Swagger ドキュメントの更新方法

```
docker-compose exec backend swag init
# または
task swag
```

# 🗃️ PostgreSQL コンテナへの接続方法

```
docker-compose exec db psql -U user -d exampledb
```

### よく使う psql コマンド

| コマンド               | 内容                         |
| ---------------------- | ---------------------------- |
| `\dt`                  | テーブル一覧を表示           |
| `SELECT * FROM users;` | ユーザーテーブルの中身を確認 |
| `\q`                   | psql 終了                    |
