## アーキテクチャのポイント

このプロジェクトは、**クリーンアーキテクチャ**と**MVC（Model-View-Controller）**原則に基づき、各フォルダとファイルが特定の責務に集中できるように設計されています。これによりコードの可読性と保守性が向上しています。

- **モデル（Model）**: `models/` フォルダにデータモデルを配置し、データベース構造とバリデーションを管理。
- **ビュー（View）**: `responses/` フォルダで API レスポンスの形式を統一。出力形式を一貫させることでフロントエンド開発も容易に。
- **コントローラ（Controller）**: `handlers/` フォルダで、各リソースのロジック処理とリクエスト・レスポンス管理を行う。
- **インフラストラクチャ層**: `infrastructure/` フォルダにデータベース接続の詳細を隔離し、アプリケーションコードとの疎結合を実現。
- **ミドルウェア層**: `middleware/` フォルダで CORS やエラーハンドリングといった共通処理を集中管理し、再利用性と一貫性を確保。

このような構造により、機能追加や修正時にも特定のレイヤーやフォルダに集中することで影響範囲を限定し、保守がしやすい設計になっています。

## API ドキュメント (Swagger) の確認方法

本プロジェクトでは Swagger を使用して API ドキュメントを提供しています。以下の手順に従って、ローカル環境で Swagger ドキュメントを確認してください。

### 手順

1. **サーバーを起動する**
   Docker を利用してプロジェクトのコンテナをビルドし、サーバーを起動します。

   ```
   docker-compose up --build -d
   ```

2. Swagger UI にアクセス
   サーバーが起動したら、Web ブラウザを開き、以下の URL にアクセスしてください。

   ```
     http://localhost:8080/swagger/index.html
   ```

   上記 URL にアクセスすると、Swagger UI を通じて API エンドポイントやリクエストパラメータ、レスポンスの例を確認することができます。

### 注意点

- ポートの確認
  8080 ポートが競合している場合、docker-compose.yml で指定されているポートを他の空きポートに変更してください。

- API の利用テスト
  Swagger UI では、各 API のリクエストを送信して実際のレスポンスを確認することができます。特に、リクエストボディの構造やレスポンス形式の確認に役立ちます。

## Swagger ドキュメントの更新

API に変更があった場合、以下のコマンドで Swagger ドキュメントを更新してください。

```
docker-compose exec backend swag init
```

以上で、Swagger を用いた API ドキュメントの確認方法は完了です。

## Docker コンテナ内での確認

PostgreSQL コンテナに接続して直接データベースを操作する方法です。

### 手順

1. PostgreSQL コンテナにアクセス

```
docker-compose exec db psql -U user -d exampledb
```

上記コマンドで、データベース名が exampledb で、ユーザーが user の場合に接続します。

2. テーブルの一覧を表示

```
\dt
```

3. テーブルの内容を確認

```
SELECT * FROM users; -- ユーザーテーブルを例としています
```

4. 終了

```
\q
```
